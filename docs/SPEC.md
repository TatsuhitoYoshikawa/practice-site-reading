# 譜読み練習アプリ 仕様書（MVP）

ピアノ初心者向けに、楽譜に沿って画面上の鍵盤を正しくタップしながら進める譜読み練習Webアプリ。

## 1. 前提

| 項目 | 内容 |
|---|---|
| 形態 | Webアプリ。スマホ横画面での利用を主想定 |
| フロントエンド | React + TypeScript（Vite） |
| バックエンド | Rails（APIモード） |
| アカウント | なし |
| データ保存 | 端末内のみ（IndexedDB） |

バックエンドはデータを保存しない「変換サーバー」として振る舞う。

## 2. 全体構成

```
[入力]                          [内部形式]              [練習画面]
楽譜画像(jpg/png) / PDF ──(OMR)──┐
URL指定の楽譜ファイル ───────────┼──> MusicXML ──> 音符列(Note Event) ──> 楽譜表示 + 鍵盤UI
アプリ内ライブラリ ──────────────┘
```

- 内部の楽譜形式は **MusicXML** に統一する。
- 練習時は MusicXML を「音符イベント列」（開始時刻・長さ・音高・手・和音グループ）に変換して扱う。
- 繰り返し記号は展開し、先頭から末尾までの一本の列にする。

## 3. 楽譜の取り込み

### 3.1 画像・PDF（OMR）
- 入力：jpg / png（複数枚可）、PDF（複数ページ可）
- 処理：Rails が受け取り、ジョブキューで非同期に OMR を実行 → MusicXML を返す
  - フロントはジョブIDでポーリングして結果を取得
  - 処理後、サーバー側の一時ファイルは削除する
- エンジン：**Audiveris**（OSS、無料。AGPL-3.0）を外部コマンドとして呼び出す
- 確認画面：元画像と認識結果の楽譜を並べて表示。MVPでは音符の手修正機能は持たない（再アップロードで対応）

### 3.2 URL指定・ファイル取り込み
- URL 指定の対応形式：MusicXML（.musicxml/.xml）、圧縮MusicXML（.mxl）、MIDI（.mid）。PDF は OMR 対応後
  - CORS 回避のため Rails が中継取得する
  - 安全対策：http/https のみ、取得先のプライベートIP禁止（名前解決した IP に直接接続）、リダイレクト3回まで、10MB・10秒上限、1分20回のレート制限
  - 形式はファイルの中身で判定する（拡張子は見ない）。MXL は Rails で展開して MusicXML にする
- 端末のファイル取り込み：MusicXML / MIDI
- MIDI → MusicXML の変換はフロントエンドで行う（`frontend/src/lib/midi.ts`）
  - 16分音符単位に量子化し、2段譜（上段ト音記号・下段ヘ音記号）にする
  - トラックが2つなら音の高い方を上段、それ以外は中央ド以上を上段に振り分ける
  - 各段は1声部にまとめ、同時に鳴り始める音は和音、次の音の開始で前の音を切る
  - 小節をまたぐ音・書き表せない長さの音はタイでつなぐ

### 3.3 アプリ内ライブラリ
- パブリックドメインの初心者向け楽曲を同梱（フロントエンドの静的ファイル `frontend/public/library/`）
  - 収録曲：きらきら星、メリーさんのひつじ、喜びの歌、ちょうちょう、かえるのがっしょう
  - `frontend/scripts/gen_library.py` で MusicXML を生成する
- 出典・ライセンス表記を楽曲ごとに保持する（`index.json`）

### 3.4 取り込み時のチェック
- 選択した手のパートの音域が **3オクターブを超える** 場合、「スマホでは鍵盤が窮屈になります」と警告する（取り込み自体は可能）

## 4. 練習画面

### 4.1 設定
- 練習する手：右手 / 左手
- 譜表の割り当て：譜表ごとに「右手 / 左手 / 使わない」を選べる（端末に保存）
  - 初期値：2段以上のパートは上段=右手・下段=左手、1段のパートはヘ音記号=左手・それ以外=右手
  - 両方の音部記号の読み取り・表示に対応する
- モード：
  - **待機モード**：正しい鍵盤を押すまで次に進まない（リズムは問わない）
  - **テンポモード**：楽譜のテンポで進む
- テンポ倍率：50〜100%（テンポモードのみ）
- 伴奏：練習しない方の手のパートを自動再生する（ON/OFF 可）

### 4.2 判定
- 正解：その音を鳴らして次へ進む
- 不正解：音は鳴らさず、**正解の鍵盤を光らせる**
- 和音：構成音をすべて押したら正解（押す順は問わない、マルチタッチ対応）
- テンポモード：
  - 判定の許容幅は ±150ms（暫定値）
  - ミス・弾き逃しがあっても停止せず、正解の鍵盤を光らせて進行
  - 終了時に正答率を表示

### 4.3 鍵盤UI
- 表示範囲：選択した手のパートの最低音〜最高音を含み、両端を白鍵に揃えた範囲
  - 音域が狭い曲でも周りが見えるよう、白鍵は最低10個表示する
- 表示範囲は曲の途中で変えない
- 白鍵は画面幅に収まるよう均等に配置する

### 4.4 楽譜表示
- 現在の音符をハイライトし、進行に合わせて自動スクロールする

## 5. 端末内データ（IndexedDB）

| ストア | 内容 |
|---|---|
| scores | id, タイトル, 取り込み元(upload/url/library), MusicXML本文, 作成日時 |
| practice_logs | scoreId, 手, モード, テンポ倍率, 正答率, 実施日時 |

## 6. 技術要素

| 用途 | 候補 |
|---|---|
| 楽譜表示 | OpenSheetMusicDisplay（または Verovio） |
| 音源 | Tone.js + Salamander Grand Piano サンプル |
| MIDI読み込み | @tonejs/midi |
| 端末保存 | IndexedDB（Dexie.js） |
| ジョブキュー | Solid Queue（Rails 8 標準） |
| OMR | Audiveris（Java）を同一 Docker イメージに同梱 |
| ホスティング | Render（8章） |

## 7. API（Rails）

| メソッド | パス | 内容 |
|---|---|---|
| POST | /api/omr_jobs | 画像/PDF をアップロードし OMR ジョブを作成 → `{ id }` |
| GET | /api/omr_jobs/:id | 状態（queued/processing/done/failed）と、完了時は MusicXML |
| POST | /api/score_fetches | `{ url }` を受け取り楽譜を中継取得 → `{ format: "musicxml" \| "midi", content, filename }`（midi は Base64）。失敗時は 422 `{ error }` |

## 8. デプロイ（Render）

| サービス | 種類 | プラン |
|---|---|---|
| frontend | Static Site | 無料 |
| backend（Rails + Audiveris） | Web Service（Docker） | 有料（Audiveris のためメモリ2GB程度を想定） |

- 無料の Web Service は 512MB・15分無通信でスリープするため、OMR 用途には向かない
- OMR ジョブは Rails プロセス内で実行し（Solid Queue を Puma 内で起動）、Background Worker は使わない
- 練習機能はフロントエンドだけで完結するため、バックエンド停止中も練習はできる

## 9. 実装の進め方
1. 練習画面（楽譜表示・鍵盤・判定・伴奏）＋ライブラリ＋ MusicXML ファイル取り込み ← 実装済み
2. Rails：URL 取り込み（MusicXML / MXL / MIDI） ← 実装済み
3. Rails：画像・PDF の OMR
